# Claude — ProjectNorth entrypoint

Nie twórz własnej wersji architektury ani stanu produktu.

1. Przeczytaj `AGENTS.md` w całości.
2. Wykonaj opisany tam repo guard i zachowaj wszystkie lokalne zmiany.
3. Przeczytaj continuity pack wskazany przez `AGENTS.md`, zaczynając od `README.md`, `docs/NORTH_STATE.md` i `docs/CONTEXT_MAP.md`.
4. Sprawdź aktualny Git status, `HEAD`, `origin/main` oraz ostatnie commity.
5. Przeczytaj task-specific evidence/research i odpowiedni kod lub dane. Nie rekonstruuj faktów z pamięci rozmowy.
6. Jeżeli masz realny dostęp do Notion, porównaj wskazane operational mirrors; Notion nie nadpisuje kanonicznego GitHub `/docs`.
7. Zanim zaczniesz zmianę, podsumuj własnymi słowami: czym jest North, co jest na produkcji, jaki jest aktywny etap, co pozostaje hipotezą i jaki jest zakres bieżącego zadania.

Każde materialne zadanie kończ zgodnie z `docs/SYNC_PROTOCOL.md`. Jeśli dokumenty są sprzeczne i konfliktu nie rozstrzygają źródła wskazane w `docs/CONTEXT_MAP.md`, oznacz `CONTEXT CONFLICT — NEEDS FOUNDER REVIEW`.
